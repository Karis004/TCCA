# TCCA 多用户升级实施方案

讨论日期：2026-11-08（香港／上海时区）。当前代码和服务器版本：`932e526`。

本文件记录实施边界与验收方案。2026-11-12 已在独立预览环境实现登录、隔离和管理界面；真实 Google 登录已通过。当前线上应用保持原状，发布步骤见 MULTI_USER_RELEASE.md。

## 已确认的产品范围

- 用户主要是常驻香港的朋友，偶尔在内地使用。
- 首次注册及主要登录方式使用 Google，不先实现邮箱密码或 Apple 登录。
- 不做邀请码。后续正常 Google 注册；保留服务器侧关闭新注册的开关，已有账号仍可登录。
- 每人独立账本，不实现家庭共享、多账本成员或组织权限。
- 每人提供自己的 OpenAI-compatible API Base URL、API Key 和 Model，用户可以修改、删除及按需查看自己的配置。
- 用户于 2026-11-12 明确要求 Google 登录不产生新增费用：采用基础 Google OAuth／OIDC 与自托管会话，不把登录依赖于 Google Cloud 90 天试用赠金或付费托管认证。
- 不回退到其他用户或站长的 AI 配置；未配置 AI 时，手动录入、预设和文字暂存仍可使用。
- 分类、支付方式、分析排除分类、默认识别币种按用户保存。统一使用香港时区。
- 为站长保留一个小型用户管理入口，避免日常直接操作数据库。
- 是否第一版包含可选 Passkey，尚待用户理解后决定；不能当作已经同意。
- 多设备登录不设单设备限制，不因在另一台设备登录而挤掉旧设备；同一账号允许添加多枚 Passkey，分别用于 iPhone、Android 等环境。

- 历史回归仅使用以上不可变快照；测试数据恢复到独立数据库，不在生产数据库跑写入测试。
- 已生成 `regression-baseline.json`，与数据库快照放在同一备份目录，服务器和本机各一份。它逐集合列出快照内 `_id` 及内容摘要，不包含新的线上记录。
- 这份快照实际完成于香港时间 2026-11-08 01:14:42.600。已离线核对，其中 164 笔流水及 4 个预设的创建时间全部早于 2026-11-08 00:00:00（香港时间），没有缺失创建时间的记录。

- 快照后用户对旧记录的主动编辑、删除单独报告，不自动恢复旧内容覆盖用户的新操作。
- 上线迁移前仍要重新完整备份，迁移范围覆盖当时的全部现有数据，包括此后新增账单；新的上线备份与本历史测试基线分开使用。

## 登录及回内地使用

Google 验证身份成功后，由本站创建自己的用户和会话。日常请求只验证本站会话，不要求每次访问 Google。

按用户 2026-11-12 的明确要求，日常体验优先保持长期登录，不采用短时间无操作即退出或每次重新打开都要求指纹的方案。计划默认使用 365 天的持久会话，正常使用时每日自动滚动续期，同时更新浏览器 Cookie 与数据库会话有效期；不是登录一年后无论使用情况都强制退出。

关闭标签页、关闭浏览器、重开主屏幕网站、手机重启及正常服务器／Docker 重启，均不应主动注销用户。会话保存在 MongoDB，认证密钥作为稳定的服务器配置保留，不随每次构建重新生成。已登录时不访问 Google 重新认证，也不自动弹出 Passkey 验证；多设备会话分别续期，互不挤下线。

主动退出、清除站点 Cookie、浏览器／系统清理数据、隐私浏览结束、会话撤销／封禁或长期完全未使用仍可能需要重新登录，不能承诺浏览器环境中的字面永久登录。IP 或 Wi-Fi／移动网络变化不作为自动退出条件。重要账号／破坏性操作如需再次验证，应局部验证，不把整个日常会话退出。

验收应覆盖关闭重开、浏览器与设备重启、前后台切换、网络／地区切换、滚动续期、服务器容器重建及多设备同时使用；在 iPhone 主屏幕网站、Safari／Chrome 和 Android 上实际确认。

Passkey 是本站绑定的通行密钥：

1. 先用 Google 登录建立本站账号。
2. 在设置中为当前账号添加 Passkey，由设备生成密钥，本站只保存公钥等验证信息。
3. 之后可以在登录页用 Passkey 直接登录本站，不依赖 Google 完成该次验证。
4. 手机通常通过 Face ID、指纹或设备 PIN 确认，生物识别信息不传到本站。
5. 新设备能否使用取决于密钥同步或原设备协助；不能把单设备密钥当成万能恢复方式。
6. 密钥绑定站点的 RP ID／域名；应先确定正式域名，不能随意改域名后期待旧密钥继续可用。

同一个本站账号可分别添加 iPhone 与 Android 的 Passkey，设备分别用 Face ID、指纹或设备 PIN 解锁。Passkey 不是用户手输的一段网站密码，也不是把生物特征上传到本站。同一密码管理器可能同步同一凭据，跨 Apple／Android 则不假定自动互通；最直接的方案是在两台常用设备上各添加一枚，均归到同一个 userId。

Passkey 不负责初次公开注册。只允许已登录用户添加密钥，保留列出、重命名及删除本人密钥的入口。封禁同样作用于 Google、Passkey 和已有会话。

认证优先采用成熟库及 MongoDB 适配器，实施时锁定受支持版本并检查当前 Next.js／React 兼容性，不手写 OAuth 或 WebAuthn 协议。

## 数据隔离与迁移

认证数据维护内部 `userId`，Google 身份通过 provider 和稳定的 provider subject 关联，业务归属不依赖可修改的邮箱地址。

业务集合统一增加 `userId`：

| 数据 | 归属与主要索引建议 |
| --- | --- |
| `transactions` | `userId`；按 `userId, date, createdAt, _id` 查询和分页 |
| `transaction_presets` | `userId`；按 `userId, createdAt, _id` 排序 |
| `pending_inputs` | `userId`；按 `userId, status, createdAt, _id` 查询 |
| `user_settings` | 每个 `userId` 唯一，包含设置及版本 |
| `user_ai_configs` | 每个 `userId` 唯一，敏感字段加密 |

索引最终根据实际查询和 explain 确定；认证库负责其会话、身份和 Passkey 索引。

所有私人读写从服务器验证的会话取得 userId，前端不能指定其他所有者。列表、分析、按 ID 编辑／删除、暂存任务认领、失败恢复、去重录入、预设、商户建议和导出都使用同一归属约束。异步任务固定保存发起人的 userId，不能因页面换账号改变执行归属。

迁移按以下顺序执行：

1. 维护窗口前重新备份；这次快照不能替代未来上线时的新快照。
2. 先确认站长的 Google 身份和目标内部 userId，不能把旧数据给第一个注册者。
3. 迁移脚本默认只预览：报告无归属记录数、目标账号和预期变更；已经有归属的数据不得覆盖。
4. 明确执行后给旧流水、预设和届时可能出现的暂存文字补归属，迁移可重复执行。
5. 核对数量及全部非归属业务字段一致；迁移分类设置时保存原始导出副本。
6. 任意缺少 userId 的遗留记录默认不可见，不再提供匿名兼容查询。
7. 只有隔离验证通过才开放新注册。

多用户写入开始之后，回滚必须使用仍具备鉴权和 userId 过滤的版本，不能回滚到当前匿名读取全部记录的代码。

## 个人设置同步与缓存

数据库作为正式来源；浏览器可缓存本人设置，缓存键包含 userId，不保存 API Key。

登录后并行读取设置、流水、预设和暂存；可先用该账号缓存展示设置，再后台核对版本。没有缓存时显示默认设置和明确加载状态。依赖分类筛选的分析等待正确设置后再预加载。

设置保存采用版本检查与合并策略；出现多设备冲突时保留本地编辑并提示重新读取，避免旧浏览器覆盖新设置。快速连续修改合并保存，提供保存状态和失败重试，不把网络错误当成已保存。

首次导入旧版浏览器设置要用户明确选择，且只导入到确认的当前账号。切换账号／退出时卸载用户页面、取消或忽略旧请求，并清空草稿、商户建议和分析缓存。分析缓存键必须包含 userId，仅失效但继续显示旧数据不够。

默认识别币种需要贯穿 AI Prompt、模型结果标准化、手动新增和不明确币种的兜底；不能只改 Prompt。明确指定币种继续优先。既有账单原币、金额和人民币换算记录保持原值；分析仍支持 HKD／CNY，不因默认识别币种变化重写历史数据。

## 用户自带 AI 配置

HTTPS 保护浏览器到本站的传输，不能替代数据库中的密钥加密。

- 服务端加密保存 API Key，主密钥独立放在服务器环境变量，并安排独立安全备份；代码和数据库备份中不混入主密钥。
- 普通设置读取返回 URL、Model 和遮挡后的 Key；用户显式点击查看时才返回本人的完整 Key，响应禁止缓存，不进入 localStorage。
- 设置支持保存、测试连接、更新及删除。测试只产生一次明确的小请求，并说明可能消耗用户的 API 额度。
- API Key 不进入共享缓存、错误追踪或请求日志；日志中的提供商错误需要脱敏。
- 当前全局 `.env` AI 配置如需迁入站长账号，只由明确的服务器端一次性步骤完成，不自动提供给新用户。
- 服务端只调用当前用户的配置。API 不兼容、没有额度或失败时保留原文及现有暂存功能。

允许用户填写 URL 会让服务器代发请求，必须限制服务器访问目标：公开 HTTPS 地址、DNS 与连接地址验证、禁止本机／内网／云元数据地址、禁止借重定向绕过验证，并限制超时与响应大小。站长现有代理如确需内部地址，应配置精确的服务器侧例外，不能向所有用户开放任意内网访问。

即使模型费由用户承担，也仍限制请求频率、并发、输入长度、单次拆单数量及存储配额，避免服务器／MongoDB 被耗尽。额度应设得足够宽，不干扰普通朋友日常记账。

## 最小管理入口

单独的小型 `/admin` 页面，只有预先确认的站长身份可进入；新用户不能自选角色，首个注册者不会自动成为管理员。

第一版建议只包含：

- 用户列表：邮箱／昵称、状态、注册时间、流水／预设／暂存数量、基础错误统计。
- 封禁与解封：封禁后撤销会话，并在每次私人 API 请求检查账号状态。
- 清理：先停用目标用户，展示范围和记录数，再通过二次确认执行；不能默认删除所有账号。
- 运维开关：关闭新注册，已注册正常用户仍可继续使用。

管理员列表不展示用户 API Key 或账单原文，不提供任意数据库查询／修改界面。角色保护禁止误封最后一个站长。将来是否允许管理员查看具体账单，应另行明确。

封禁是事后控制，不能替代请求和存储上限。数据库级备份仍由运维流程负责，不需要为了备份先开发大型后台。

## 域名与上线依赖

历史记录：2026-11-08 使用旧域名 `harborside.duckdns.org` 时 HTTPS 尚未部署。用户于 2026-11-12 确认新正式入口为 `https://tcca.duckdns.org`，本轮直接 HTTPS 请求返回 200 且页面标题为 TCCA，未跳过 TLS 验证。本轮没有更改网关、证书或 Google 计费配置。

正式入口统一为 `https://tcca.duckdns.org`，Google 回调为 `https://tcca.duckdns.org/api/auth/callback/google`；后台规划为同域名 `/admin`。共享 HTTPS 入口属于独立 `personal-gateway` 项目，TCCA 不持有网关或证书密钥。旧域名回调不再作为正式配置。

HTTP／HTTPS、IP／域名、不同端口是不同浏览器来源。现有手机分类设置不会自动从旧 HTTP 来源出现在新 HTTPS 来源。部署强制跳转前须安排旧来源设置导出／导入，或先实现受控的设置迁移，不能把设置丢失误认成流水丢失。

免费域名不是必须换库或购买付费域名的理由。先以现有域名验证 HTTPS、Google 回调及域名配置要求；不能仅凭 DNS 能解析就认为 OAuth 已完成。

上线需要填写正式站点 URL、Google Client ID／Client Secret、认证会话密钥、AI 配置加密主密钥，以及站长身份的受控初始化配置。敏感值放服务器环境文件，不写代码或聊天记录。

证书可采用 Let's Encrypt 并自动续期；代理统一正式 HTTPS 入口，生产 Cookie 使用 Secure／HttpOnly 及正确 SameSite 配置。私有数据不得被代理／CDN 共享缓存。原应用端口后续限制为代理可达，防止绕开正式入口。

## 验收与分期

1. 数据保护：已完成本轮快照、异地到本机副本和隔离恢复演练；手机本地设置仍需导出／导入。
2. 本地实现：用户模型、Google 会话、全部业务隔离、个人设置和自带 AI 配置；包含已确认的多设备 Passkey。
3. 本地验证：两个账号互不可访问；切号无旧缓存；被封禁会话立即失效；来源 ID、批量录入和异步任务不能越权；SSRF 防护、加密及日志脱敏通过测试；既有记账功能回归通过。
4. 线上准备：正式域名、HTTPS 和 Google 凭据就绪后，再备份、迁移、部署和手机实测，最后开放注册。

本轮已完成本地实现与独立预览库归属迁移，线上数据归属和生产版本尚未改动。具体验收结果和待实测项目见 MULTI_USER_RELEASE.md。
